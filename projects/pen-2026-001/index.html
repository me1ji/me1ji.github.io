SEC-2026-001

Kioptrix Level 1

Executive Summary

During the security assessment of the Kioptrix Level 1 machine, we identified a Critical vulnerability related to an outdated and unpatched file-sharing service (Samba 2.2.1a).

If exploited, an attacker could gain complete, unrestricted control over the target system including access to all files, user accounts, and sensitive data without needing a username or password.

The attack was carried out successfully in a controlled lab environment, confirming that the vulnerability is real and easily exploitable using freely available tools. The most critical takeaway is that running outdated software with no firewall protection can allow an outsider to take over an entire system in a matter of minutes.

Vulnerability Details

  • Vulnerability Type: Stack-Based Buffer Overflow
  • CVE: CVE-2003-0201
  • Affected Component: Samba service (SMB port 139), specifically the trans2open request handler

Description: Samba versions 2.2.x contain a critical buffer overflow in the way trans2 requests are processed. The flaw exists in code that runs before any authentication check, meaning no credentials are needed to trigger it. By sending a specially crafted trans2 packet, an attacker can overflow the stack buffer and overwrite the return address, redirecting execution to arbitrary shellcode. Metasploit’s exploit/linux/samba/trans2open module automates this entirely.

Proof of Concept (PoC)

Phase 1: Reconnaissance

Host Discovery

Run nmap -sn to discover live hosts on the network.

There are 5 hosts the 2.1 is our network gateway and the 2.2 & 2.3 are the network interface cards and by process of elimination we now know that our target machine’s ip is 10.0.2.4

Service Fingerprinting

Once the target has been identified run nmap -O and nmap -sV to fingerprint the OS and open services. Port 139 (SMB) is found open

Use msfconsole which launches the Metasploit Framework for vulnerability scanning and exploitation.

We now know that our target is using samba 2.2.1a and running linux

Phase 2: Initial Access

Go into metasploit and search for samba exploits at the very bottom we can see that an exploit named trans2open targets samba 2.2.x so lets use it

use exploit/linux/samba/trans2open which selects the specific exploit module targeting a buffer overflow in Samba.

Root Cause Analysis

The vulnerability exists because Samba 2.2.x fails to perform proper bounds checking on user-supplied data in the trans2 request handler before the buffer is written to the stack.

  • Primary Cause: No input validation or bounds checking on incoming SMB packet data.
  • Technical Breakdown: The trans2open function copies attacker-controlled data into a fixed-size stack buffer without verifying its length. This overwrites the return address and redirects execution to the attacker’s shellcode. The exploit fires pre-authentication, so there is no login barrier whatsoever.
  • Compounding Factor: The Samba daemon was running as root (uid=0), so successful exploitation immediately yielded the highest possible privilege level with no further steps needed.

Recommendations

Short-Term Fix (Patch)

  • Immediately upgrade Samba to version 2.2.8a or higher, or migrate to a currently supported release.
  • Block TCP/UDP ports 139 and 445 at the network perimeter firewall. SMB should never be exposed to untrusted networks.

Long-Term Prevention

  • Enforce the Principle of Least Privilege: run all services under dedicated low-privilege service accounts, never as root.
  • Disable null (unauthenticated) sessions by adding restrict anonymous = 2 to smb.conf.
  • Conduct regular vulnerability scans and patch audits to catch outdated software.
  • Implement host-based firewalls (e.g., iptables) as a secondary defense layer.
